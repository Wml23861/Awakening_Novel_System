# 文档与目录中文化改名设计

日期：2026-10-30

## 目标与范围

仅将 `00_SYSTEM` 至 `10_TOOLS` 这十一组顶层业务目录及其内部 Markdown 文档名称中的英文改为中文，不翻译正文，不修改 Python 脚本文件名，不改变项目阶段或创作资料。

同步修改文档链接、配置引用、脚本路径常量及相关测试，使改名后的项目仍可定位文件并通过验证。除路径引用和必要测试外，不改动文档正文。

## 保留项

- 根目录所有文件和目录名称均不在本次改名范围内，包括 `CLAUDE.md`、`README.md`、`CHANGELOG.md` 和工程总纲。
- 保留 `.claude/` 及其全部内容。
- 保留 Python 脚本、测试脚本及其他非文档文件名称。
- 四部名著 Markdown 与 `四大名著.txt` 不改名、不移动、不改内容。
- 不处理上述保留项和原著正文中的英文。

## 改名原则

- 保留 `00` 至 `10` 的数字前缀和现有目录层级，只翻译英文部分。
- 范围内的普通 `README.md` 按所在目录用途改为中文说明名称。
- 系统文档、模板和验收报告采用含义明确的中文名称。
- 范围内已有中文名称的文档和目录保持不变。

## 引用与验证

1. 改名前建立旧路径到新路径的明确映射，并检查目标路径是否已存在。
2. 改名后更新 Markdown 链接、Claude 配置中的路径和 Python 工具中的目录常量。
3. 检查旧业务路径是否仍有引用，检查所有目标文件是否存在。
4. 运行项目校验和 Python 单元测试，如实记录结果。
5. 检查 Git 状态，确认四部名著原有改动未被触碰；不擅自提交。

## 验收标准

范围内普通业务目录和 Markdown 文档名称不再含英文；保留项符合上述例外；链接和路径引用已同步；适用测试通过；原著文件及其未提交改动保持原样。
