# 项目工作流

版本：0.1.0

## 1. 统一任务入口

1. 读取项目状态，确认当前 PHASE 和用户授权范围。
2. 读取创作宪法及对应研究、写作或审稿协议。
3. 盘点输入文件与缺失资料，说明本次交付物。
4. 按角色分工执行，保存可检查的过程文件。
5. 实际验证，更新状态和变更记录；完成后停止于阶段门槛。

## 2. 阶段路线

PHASE 0 初始化 → PHASE 1 原著准备 → PHASE 2 四书逐回研究 → PHASE 3 交叉研究 → PHASE 4 商业研究 → PHASE 5 L1—L4 训练 → PHASE 6 五个原创核心创意 → PHASE 7 世界观与人物 → PHASE 8 全书与分卷架构 → PHASE 9 前 10 章压力测试 → PHASE 10 前 30 章真实商业验证 → PHASE 11 长期连载。

建议研究顺序为《西游记》《水浒传》《三国演义》《红楼梦》，仅为执行顺序，不是价值排序。四书每部独立验收。

## 3. 后续正式章节流程

用户任务 → 读取规则与状态 → 读取人物/世界/剧情档案 → 剧情架构师设计章节 → 人物自主行动模拟 → 因果与连续性检查 → 正文作者创作 → 专项检查 → 独立责任编辑终审 → 读者模拟和反模板压力测试 → 不通过则修改复验，通过则保存正式章节 → 更新剧情档案与复盘。

## 4. 命令入口

项目命令在 `.claude/commands/` 中，包括 `/research`、`/cross-study`、`/commercial`、`/train`、`/idea`、`/world`、`/characters`、`/outline`、`/chapter-plan`、`/write`、`/review`、`/audit`、`/reader`、`/evolve`、`/status`。命令只是提示入口，不绕过阶段状态、证据要求或用户确认。

## 5. 反馈与进化

真实读者反馈、平台数据、AI 模拟和内部审稿分开记录。复盘经验先进入“待验证经验”；只有具有案例、适用边界、副作用评估和实际验证的内容才进入稳定规则。失败案例保留，不因难看而删除。

## 6. 停止条件

阶段完成、关键资料缺失、核心设定冲突、需用户选择方向、版权/来源无法确认或验证失败时暂停并报告，不以猜测继续推进。
