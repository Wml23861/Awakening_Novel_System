# 版本与变更管理

版本：0.1.0

当前目录不是 Git 仓库，本阶段不擅自初始化、提交或推送。无论未来是否采用 Git，均执行以下留痕规则。

## 1. 原始资料保护

用户提供的总纲和四部名著文件保持原样。候选资料登记文件名、路径、大小和校验值；规范化副本与原文件分开，任何清洗都生成新文件并记录操作，不覆盖原件。

## 2. 文档版本

系统规则使用版本号和日期。核心设定、总纲、大纲和正式正文重大修改前保留历史版本到 `11_ARCHIVE/` 对应目录。文件名包含可排序日期或版本，避免“最终版2”等含混命名。

## 3. 规则变更记录

每次规则变更记录：原规则、修改原因、适用范围、预期效果、可能副作用、验证结果和版本号。未验证经验不得直接升级稳定规则。规则可合并、删除或调整，但须说明理由，不无限累积。

## 4. 创作变更记录

章节修改保留原稿、审稿依据、修改稿和复验结果。世界规则新增须关联受影响档案与章节；用户确认的核心设定不得未授权改写。废弃设定归档，不冒充从未存在。

## 5. 配置同步

`.claude/` 是实际运行配置，`08_技能/` 和 `09_智能体/` 保存索引与版本说明。变更运行配置时同步更新索引和变更记录，避免维护两份容易漂移的正文副本。

## 6. 变更后检查

检查实际文件清单、差异、意外变化和测试结果。若未来使用 Git，须由用户明确要求后再初始化、提交或推送，并遵循常规提交格式。
